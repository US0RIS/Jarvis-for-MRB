# World Armor — Phase 3B: bounded evidence attention and private inbox

**Status:** stacked draft implementation on `jarvis/world-armor-attention-inbox`,
based on [standing watches](WORLD_ARMOR_WATCHES.md). Neither a PR nor CI
means installed or accepted on the operator's actual Windows host/iPhone.

## Operator-facing contract

A saved, explicitly opted-in World Armor watch may now enroll **exactly one**
of four typed predicates at creation:

| Rule | Required threshold | When a private notice is saved |
|---|---|---|
| `off` (default) | none | Never |
| `modelled_aqi_threshold_crossed` | 50–300 US AQI | Modelled AQI crosses upward from below the configured number on a comparable, fresh model sample |
| `new_usgs_report` | M2.5–M8.0 | An official USGS report meeting the magnitude threshold is first received during this investigation, has a publisher occurrence time no older than 24 hours, and is not the watch baseline |
| `new_nws_alert` | none | A different official NWS point-alert ID first appears in the investigation after its baseline; provider issue time and exact alert polygon are NOT available |

Predicates are deterministic, source-qualified, not generated by the local
8B model, and never assert causation, verified event onset, safety,
evacuation status, wrongdoing, identity or action permission. The first
watch sample establishes a baseline; it does **not** generate a flood of
"new" incident notices. AQI compares model values for the same selected
query point, not local street-level sensors. First-received NWS/USGS
records may describe existing or previously reported conditions.

Enrollment is bounded by the existing region/sampling budget, expiry and
the standalone runner opt-in; enabling a rule does not start the runner.
Only samples from `real_adapter` mode can generate notices, and both
latest and comparison baseline must be real-adapter receipts. The selected
source must report `ok` in both samples; missing/partial/stale/unavailable
source coverage suppresses the rule, not a notice asserting normalcy.
An unrelated source being down does not transform a healthy source report
into a verified physical event.

A watch can save **at most one notice per sample**, selecting the largest
qualifying USGS magnitude (or lexically earliest NWS ID) if several
qualify. A per-watch 30–360 minute cooldown suppresses further matches,
including different record IDs; suppressed matches are not queued for
late replay. Native source ID de-dup prevents repeated NWS/USGS alerts
for the same ID from generating another notice. The system never sends
one email, message, remote push or other notification automatically.

## What delivery means NOW

**Durable private inbox:** notices are stored in the same expiring
`world_armor.sqlite3` as the enrolled watch. Each contains exactly
one traceable sample ID, watch ID, optional primary observation ID,
provider, source record ID, source/model timestamp when known, separate
Jarvis receive time, capture time and carefully qualified summary.
`GET /world-armor/v1/notices?investigation_id=<id>` returns the
latest 100, unread count and explicit delivery mode
`private_inbox_only_no_remote_push`.

**Foreground native banners:** the iPad/iPhone World Armor view
fetches its selected region's private inbox when opened and at about
60-second intervals **while active**. The operator must turn on
"In-app banners while World Armor is open" to see a native SwiftUI alert
when a *new* notice arrives during that viewing session. Historical
unread notices are displayed in the inbox but do not replay old banners
when reopening or refreshing the view. The view hides notice content
when the app leaves the foreground.

This is **not an APNs/remote push implementation, iOS BackgroundTasks
delivery, an OS-level local notification, or reliable closed-app or
offline emergency alerting**. Network loss does not clear last-known
evidence or imply normal conditions. The runner continues locally
only if explicitly running on the installed host. Offline phone
cannot obtain new notices.

## Private API and deletion

The following endpoints use the already configured private bearer
token and `Cache-Control: private, no-store`:

- `POST /world-armor/v1/watches` adds optional `attention_kind`,
  `attention_threshold` and `attention_cooldown_minutes` to the
  existing typed region/cadence/budget/TTL enrollment. They are
  immutable for that grant: stop/forget, then enroll a new one to change
  a rule. Omitted rule means `off`, not automatic notifications.
- `GET /world-armor/v1/notices` accepts optional
  `investigation_id`, `watch_id`, `unread_only`.
- `POST /world-armor/v1/notices/read` with
  `{"notice_id":"<id>"}` marks exactly one notice read idempotently.
- `POST /world-armor/v1/notices/forget` deletes exactly one saved
  notice without deleting its source receipt.
- Watch Forget cascades that watch's notice rows. Region Forget/expiry
  cascades everything under the region. Read, list and forget remain
  available while collection/attention flags are off.

No API endpoint accepts freeform executable predicates, arbitrary URLs,
notification destinations, unsolicited recipient addresses or actions.
A notice cannot dispatch a message, request Agency/Conductor, operate
a machine, spend funds or trigger a trade.

## Operational limits and acceptance

Notice creation happens **inside the same SQLite write transaction**
as the active watch completion, after verifying the exact lease. If
the watch was stopped/forgotten or the lease superseded before this
transaction, no notice is created. Collection already committed
before stopping cannot be retroactively erased by stop; Forget
handles deletion. A watch's separate receipt and any notice describe
a *saved provider report*, not live verified situational awareness.

The comparison uses the last two retained investigation receipts,
which might include an interleaved foreground sample or another
watch. It refuses to emit a notice unless the latest receipt time
is **exactly** the just-collected watch sample time. Same-time
ambiguous receipts and mixed fixture/real-adapter baselines do not
become notifications.

Run exact-head:
```text
python -m unittest discover -s tests -p "test_world_armor_attention.py" -v
python -m unittest discover -s tests -v
python -m jarvis_mrb.world_acceptance_check
```
Plus Windows full regression and native iOS simulator build. Synthetic
fixtures and CI never establish live provider entitlements, notifications
on a real iPhone, or continuously running Windows deployment.

## Next separate phases

OS-level push/closed-app delivery requires a real opted-in transport
and verifiable delivery acknowledgments, platform permission review,
per-recipient routing, and token/secret lifecycle. Geospatial alert
polygons, licensed cameras, road impacts, carrier/aircraft/ship reports,
policy-aware worker distribution and physical actions remain separate
unimplemented capabilities.
